# Errors.txt (e-hentai): превью в «Full size» — разбор и фикс (2026-10-12)

Репорт: галерея `https://e-hentai.org/g/4249104/719e4d495b/`, «скан выдаёт 288 изображений
при параметрах All domains и Full Size, при этом в результаты попадают как полноразмерные
изображения, так и заведомо мелкие thumbnails».

Подписи «All domains» / «Full size» есть только в попапе расширения (`src/` их не содержит) —
репорт про `extension/`, не про десктоп-приложение.

## Как воспроизведено

Свежий CfT 137 с распакованным расширением, реальная страница, живой клик по кнопке попапа.
Сеть: только HTML страниц (медиафайлы не скачивались, загрузки не запускались).

- `.ext-dev-loop/review_2026-10-12/repro_eh.json` — до правки
- `.ext-dev-loop/review_2026-10-12/verify_eh.json` — после правки
- `.ext-dev-loop/review_2026-10-12/thumb_bucket.json` — проверка корзины Thumbnails
- `fetch_eh*.py`, `where_thumbs*.py` — разбор структуры страниц и того, что отдаёт каждая ссылка

## Что происходит на самом деле

Замер до правки: **298 записей, ВСЕ с `source: "linked-img"`**, из них **285 — `ehgt.org/w/…webp`**
(превью), 13 — `hath.network` (настоящие оригиналы). Цепочка:

1. `content_script.js` отдавал в discovery **каждый** `<a href>`: 60 ссылок, из которых 39 —
   навигация сайта (Front Page, Watched, Popular, Torrents, теги, пагинация `?p=N`, ToS, форум,
   вики) и только 21 — контентная. Клетки галереи — это `<a>`, чьё превью является
   `background-image` (в `<img>` его нет), поэтому ветка «`<img>` внутри `<a>`» их не видела, а
   «случайная» вторая ветка (все якоря) добавляла их вместе с навигацией.
2. `discoverFullsize` берёт **первые** `LINKS_CAP = 50` — навигация, идущая в DOM раньше, съедала
   бюджет: из 20 реальных ссылок-клеток в выборку попадало ~11.
3. Для каждой HTML-страницы `processLink` (фолбэк `<img>`-дампа) помечал **каждую** найденную
   картинку как `source: "linked-img"`, а `linked-img` входит в `FULLSIZE_SOURCES` (`shared.js`).
   Отсюда: главная страница сайта = 25 превью, `/popular` = 62, страницы пагинации = по 20 —
   всё это попадало в «Full size». Признак «это страница-сетка, а не страница с оригиналом» нигде
   не проверялся.
4. Отдельная (не исправленная) особенность: правило e-hentai в `sieve.json` — «альбомное»
   (`link` + JS `res`), и его `res` использует API Imagus (`Port.send`, `this.stack`, `this.show`)
   с отдельным сетевым запросом на каждую страницу просмотра. `parseSieve` (`sieve.js:30`)
   отбрасывает правила без пары `img`+`to`, а JS-`res` в нашем конвейере не исполняется — значит
   **штатного апгрейда превью→оригинал для e-hentai нет**, и вся работа ложится на слепой дамп.

## Правки

| Файл | Что сделано |
|---|---|
| `extension/content_script.js` | Кандидатом в discovery считается только ссылка, которая **показывает медиа**: `<img>/<picture>/<video>/<canvas>` внутри, либо `background-image` у самой ссылки или у потомка (`presentsMedia`). Прочие ссылки собираются, но **после** медийных (`links.concat(linkRest)`) — бюджет `LINKS_CAP` достаётся контенту, а не «Watched»/«Faq». Прямые ссылки на файл по-прежнему уходят в `a-link`. |
| `extension/background.js` | Новая `classifyPageImages(count)`: одна картинка на странице — это оригинал (`linked-img`, полноразмер), **несколько — это сетка самой страницы** (`page-img`, в `FULLSIZE_SOURCES` НЕ входит → попадает в корзину Thumbnails). Плюс: если сработало правило сива (`res`-regex), `<img>`-дамп не запускается вовсе — знание сайта главнее слепого регекса. |
| `extension/shared.js` | Комментарий: почему `page-img` намеренно не в `FULLSIZE_SOURCES`. |
| `extension/tests/page_image_classification.test.mjs` | Новый тест (реальные исходники + фейковый DOM): классификация страницы и порядок ссылок (медийные раньше навигации, клетка-фон = кандидат, `a-link` не становится probed-страницей). |
| `extension/tests/content_scan.test.mjs` | Стаб якоря дополнен `querySelector`/`getAttribute("style")` — без этого он перестал отражать настоящий элемент. |

## Остатки и что НЕ сделано

- Одна запись из 21 — `https://ehgt.org/b/2026-10/04.webp` (картинка со страницы `news.php`): у
  этой страницы ровно одна картинка, поэтому эвристика «одна картинка = страница-оригинал» её
  пропускает. Отличить «баннер навигационной страницы» от «оригинала на странице просмотра»
  обобщённо нечем (размеров в HTML нет, HEAD их не даёт) — это осознанное ограничение правила.
- Галерея содержит 140 изображений на 6 страницах; скан берёт текущую страницу + до 50 ссылок,
  поэтому «все 140» не соберутся. Это свойство `LINKS_CAP`, а не регресс.
- Настоящий «альбомный» путь Imagus для e-hentai (список `/s/`-страниц → картинка максимального
  разрешения с `hath.network`, до 500 штук) по-прежнему не реализован: JS-`res` требует API Imagus
  и асинхронных запросов на каждую страницу. Кандидат на отдельную задачу — декларативное
  подмножество `res` (регекс по HTML страницы) вместо полного JS-движка.
- Воспроизведение требует интернета и внешнего сайта; в тестах проекта закреплены только
  локальные фикстуры — регресс по этому классу ловится юнит-тестом, а не E2E.
