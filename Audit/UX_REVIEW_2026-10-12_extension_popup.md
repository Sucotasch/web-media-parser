# UX/UI-ревью попапа расширения — 2026-10-12

Скиллы: `interaction-design` (правила + механический детектор `impeccable`), `better-layout`
(группировка/отступы/выравнивание). Смотрели только попап: `extension/popup/{popup.html,popup.css,popup.js}`.
Ничего в поведении сканирования/скачивания не менялось (кроме явно отмеченного ниже).

## Как измеряли (не «на глаз»)

Живой CfT 137 с распакованным расширением, попап открыт как страница, замеры — через CDP
(`.ext-dev-loop/review_2026-10-12/cdp.mjs`, выражения `measure.expr.js` / `layout.expr.js` /
`scenarios.expr.js`): вычисленный контраст (WCAG-формула по фактическому фону), размеры целей,
`scrollWidth > clientWidth` (усечение), computed `outline` при фокусе, и **настоящие нажатия Tab**
(`Input.dispatchKeyEvent`), а не фильтр по `tabIndex`.

Две ловушки харнесса, из-за которых первый замер «показывал» зависший попап:

1. фоновая вкладка попапа отвечает на `Runtime.evaluate`/`captureScreenshot` не всегда — Chrome
   её подмораживает; лечится `Target.activateTarget` + `Page.reload`;
2. после `chrome.runtime.reload()` в уже открытой вкладке **нет контент-скрипта** —
   скан падает с `Receiving end does not exist`, пока страницу не перезагрузят.

Фикстура: `.ext-dev-loop/fixture/` на 9811 (7 медиа, 3 fullsize). Единственный домен в фикстуре,
поэтому ветка «фильтр скрыл всё» проверена синтетическим option (тот же код-путь), плюс
добавлена страница без медиа `empty.html` для честной проверки «пусто» ≠ «пусто из-за фильтра».

## Найденные баги (это не косметика)

1. **Действия футера были недоступны с клавиатуры.** `#sieve-btn` и `#sieve-update-btn` — `<span>`
   с `cursor: pointer`: Tab их пропускал, Enter/Space не работали. Теперь это кнопки, а файловый
   диалог открывает обработчик на `#sieve-btn` (кнопка внутри `<label>` — ловушка: активация
   label может съесть клик по интерактивному потомку, поэтому input вынесен из label).
2. **Счётчик на `Download` терялся навсегда после одного переключения `Page only`.**
   Замер: `Download 3` → `Parse Page` → **`Download`** (span `#selected-count` удалён из DOM, а
   ссылка `selectedCountSpan` осталась висеть на отсоединённом узле). Теперь метка
   пересобирается, а оба счётчика перезапрашиваются там, где используются.
3. **Ложный аффорданс.** Превью обещало клик (`cursor: pointer`, hover-opacity) без действия.
   Решено в пользу настоящего действия: клик/Enter открывает файл в новой вкладке.
4. **«Пусто» и «пусто из-за фильтра» выглядели одинаково.** `renderMediaList` при нуле строк
   после фильтра показывал «No media found on this page.». Теперь ветки разные, текст просит
   сменить источник/домен; для действительно пустой страницы формулировка сохранена.
5. **Контраст 3.78:1** (нашёл детектор `interaction-design`) и **невидимое кольцо фокуса** —
   доступность, а не вкус.

## Осознанные решения и границы

- **Названия `Save (Chrome)` и `Download` не менял.** Они задокументированы в `README.md` (таблица
  режимов); переименование потянуло бы правку документации и привычек. Вместо этого добавлены
  `title`, объясняющие разницу («Chrome's own downloader» vs «send to the desktop app queue»).
  Кандидат на отдельную задачу: «Save files» / «Send to app».
- Контраст отключённых кнопок (`#777` на `#333` ≈ 2.8:1) не трогал: WCAG 1.4.3 исключает
  неактивные контролы, а причина недоступности теперь объяснена в `title`.
- Клик по превью — **новое поведение** (раньше не делал ничего).
- Детектор в этой оболочке возвращает код 126 (`exec: ... node.exe: cannot execute`) — это баг
  Git-Bash-обёртки, не вердикт: `impeccable` при этом печатает корректный JSON на stdout, по нему
  и судил. `--json` и `[]` — единственный надёжный сигнал здесь.
- **Нативный диалог выбора файла** в headless не открывается в принципе: проверена проводка
  (обработчик → `input.click()`) и сам путь загрузки правил, но не появление системного окна.
  Это стандартный для MV3 паттерн (раньше то же делал `<label>`), отдельно не проверялось.
- PNG-скриншоты (`popup_idle.png`, `popup_after.png`) сняты, но глазами я их не смотрел —
  все выводы выше сделаны по числам из DOM, а не по картинке.
