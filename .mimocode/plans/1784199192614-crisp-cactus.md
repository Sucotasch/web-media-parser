## Proposed Solution Evaluation

### Priority 0: Critical Bugs (must fix first)

#### BUG-01: Resume drops pending downloads
**Proposed fix:** Restore all download_queue_items without filtering by downloaded_files.
**Risk assessment:** SAFE. The fix is correct: downloaded_files is populated at enqueue time, not completion time. On resume, items in the download_queue that were never completed should be restored. No double-download risk because completed items are already removed from download_queue_items by get().
**Performance:** Neutral — slightly more downloads (correct ones).

#### BUG-02: Session path mismatch
**Proposed fix:** Add task_state_path helper, use it in save/load/delete.
**Risk assessment:** SAFE. Aligns all three paths to the same formula. The delete path is currently broken (trying to delete a file that doesn't exist), so any aligned path is an improvement.
**Performance:** None.

#### BUG-03: one_shot ignored on direct Start
**Proposed fix:** Pass one_shot from checkbox to add_task and ParserManager.
**Risk assessment:** SAFE. Reuses existing _launch_parser_for_task path. No new semantics.
**Performance:** Fewer requests when Page only works — intended.

#### BUG-04: Double task_done
**Proposed fix:** Remove task_done from try block, let finally handle it.
**Risk assessment:** SAFE. Matches asyncio.Queue contract (one task_done per get). The fix is minimal and correct.
**Performance:** Improves reliability — no worker crash.

#### BUG-05: Pause/switch race
**Proposed fix:** Mark PAUSED first, then stop, then clear_active. Also disconnect old signals.
**Risk assessment:** NEEDS CARE. The proposed fix in the audit is mostly correct, but the signal disconnect is critical. Without disconnecting old parser_manager.task_ended signal, the old parser's task_ended("stopped") will fire on the new task. The audit's code sketch doesn't explicitly show disconnect(). I recommend adding signal disconnect in _launch_parser_for_task or _pause_current_for_switch.
**Performance:** None.

#### BUG-06: Truncated files after Stop
**Proposed fix:** Write to .partial, rename on success.
**Risk assessment:** SAFE with one caveat: the rename must be atomic (os.replace). The .partial extension is already used by multi-thread path, so cleanup glob is compatible. The size check cleanup already removes size==0 files but misses non-zero truncated — .partial fix addresses this.
**Performance:** One extra rename per download — negligible.

#### BUG-07: asyncio.Event in threads
**Proposed fix:** Add threading.Event for executor threads.
**Risk assessment:** SAFE. Same semantics, clearer concurrency model. The is_set() read is practically safe under GIL but using threading.Event is correct contract-wise.
**Performance:** Negligible.

#### BUG-08: Bad origin Referer
**Proposed fix:** Use f"{scheme}://{netloc}" instead of get_domain().
**Risk assessment:** SAFE. Matches downloader behavior. Standard Origin/Referer form.
**Performance:** None.

#### BUG-14: Cookie sync without domain
**Proposed fix:** Add domain=hostname, path="/" to cookies.set().
**Risk assessment:** SAFE. Cookies will be scoped to the correct domain. The cookies come from _sync_session which is per-URL, so hostname from the parsed URL is correct.
**Performance:** None.

### Priority 0: Extension Bugs

#### E01: sieve.js dead
**Proposed fix:** Wire sieve.js into popup.html, apply transforms after scan.
**Risk assessment:** NEEDS CARE. The audit correctly notes that JS rules (to starting with ":") need page context (document), which popup DOM doesn't have. The recommended first-pass approach is correct: only apply string rules in popup, leave JS rules for content_script port. This is a two-phase fix.
**Performance:** CPU only, <100ms on 200 URLs.

#### E02: Relative URLs dropped
**Proposed fix:** Use new URL(url, baseUrl).href for resolution.
**Risk assessment:** SAFE. Standard URL resolution. May increase link count — already capped at 50.
**Performance:** More discover fetches — capped.

#### E03: cookies.getAll({tabId})
**Proposed fix:** Use chrome.tabs.get(tabId) first, then cookies.getAll({url: tab.url}).
**Risk assessment:** SAFE. Correct API usage. Two extra API calls (tabs.get + cookies.getAll) but acceptable.
**Performance:** Negligible.

#### E04: No getUA handler
**Proposed fix:** Add getUA branch to content_script.js message listener.
**Risk assessment:** SAFE. Pure addition.
**Performance:** None.

#### E05: Desktop enqueues without auto-start
**Proposed fix:** Auto-start one_shot task if no active task.
**Risk assessment:** NEEDS CARE. The proposed Option A (auto-start when idle) is correct for one_shot tasks. Must not auto-start non-one-shot deep parse tasks without user confirmation. The GUI-thread marshaling (QTimer.singleShot) is critical — the HTTP callback runs in aiohttp thread.
**Performance:** None — same as user pressing Start.

#### E06: Sieve break after first match
**Proposed fix:** Only break after successful res capture.
**Risk assessment:** SAFE. More rules tried = better recall. Deduped via seen set.
**Performance:** Slightly more iterations on multi-rule domains — negligible.

### DEV_GUIDE Work Packages

#### WP-1: segment-aware URL classifier
**Proposed fix:** New should_skip_crawl_url function with path-segment matching.
**Risk assessment:** NEEDS CARE. The proposed DEFAULT_LINK_SKIP_SEGMENTS set is reasonable but some entries need consideration:
- "tag"/"category" — the guide itself notes these may block galleries. Recommend making them deprioritize (lower queue priority) rather than hard-skip.
- "redirect"/"go"/"out" — some sites use these for actual content links. Recommend only hard-skip for legal/auth, deprioritize for others.
- The ad_hosts list is safe — known ad networks.
The function design is correct: segment-aware (not substring), with extra_stop_words as additional segments.

#### WP-2: soften SIGNIFICANT_MEDIA_IGNORE_PATTERNS
**Proposed fix:** Remove "thumb"/"thumbnail" from hard ignore, add THUMBNAIL_URL_HINTS as soft hints.
**Risk assessment:** SAFE. Current behavior drops legitimate content. The soft-hint approach preserves recall while still allowing filter improvements.

#### WP-4.1: from_image overwrite fix
**Proposed fix:** Check existing link entry before overwriting; preserve from_image: True.
**Risk assessment:** SAFE. The fix is minimal: only skip overwrite when existing entry has from_image: True or priority >= 10. Images are extracted before links in parse(), so from_image entries should already exist when _extract_links runs.

#### WP-3.2: WordPress size strip
**Proposed fix:** Add try_strip_wp_size_suffix after site-specific rules fail.
**Risk assessment:** SAFE. Only applies regex to strip -300x200 before extension. Reversible pattern. Does not strip query params globally.

## Key Cautions

1. **BUG-05 signal disconnect** — The audit's fix sketch doesn't explicitly show disconnecting old parser_manager.task_ended signal. This is critical: without it, old parser's task_ended("stopped") will corrupt the new task.

2. **WP-1 tag/category** — Hard-skipping these segments may block legitimate galleries. Recommend deprioritize (priority ×0.05) rather than hard-skip.

3. **E01 sieve.js JS rules** — Cannot run in popup (no page DOM). First-pass: only string rules. Phase 2: content_script port for JS rules.

4. **E05 auto-start** — Must only auto-start one_shot tasks, not deep parse. Must marshal to GUI thread.

5. **No architectural refactor** — All fixes are surgical patches. Do not rewrite ParserManager, PriorityURLQueue, or extension architecture while fixing bugs.
