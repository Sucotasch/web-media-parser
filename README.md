# Web Media Parser

**Desktop-приложение для интеллектуального парсинга и загрузки медиафайлов с веб-сайтов.**

Автоматически обнаруживает изображения и видео, отличает полноразмерные версии от миниатюр, обходит защиты (cookie-consent, age-gate, JS-редиректы) и адаптируется к структуре конкретных сайтов через систему паттернов.

---

## Возможности

### Умное обнаружение медиа
- **Full-size из thumbnails** — преобразует URL миниатюр в полноразмерные изображения через встроенные паттерны и правила Imagus (включая JS-правила)
- **Приоритизация URL** — медиа-ссылки обрабатываются первыми, навигационные — в последнюю очередь
- **Фильтрация «мусора»** — автоматический пропуск иконок, баннеров, tracking-пикселей, SVG и GIF-анимаций
- **Распознавание lazy-load** — извлекает изображения из `data-src`, `srcset`, inline-CSS и JavaScript-кода
- **Ограничение на домен** — макс. 2 одновременных запроса к одному домену (парсинг + скачивание)

### Обход защит и динамического контента
- **Cookie-consent** — автоматическая установка согласий на использование cookies
- **Age-gate / Gateway** — кнопки «Мне есть 18», «I agree» и аналогичные: статическое извлечение consent-кук из JS-обработчиков (всегда) + точечный DOM-клик через Deno при `js_engine=deno`; обход гейта один раз на домен (кэш кук)
- **JS-редиректы** — обнаружение и переход по JavaScript-редиректам (до 5 редиректов)
- **HTTP 429** — автоматический backoff с учётом `Retry-After` заголовка
- **Fallback aiohttp → requests/curl_cffi** — если сервер блокирует асинхронные запросы, используется sync `requests` (или `curl_cffi` с браузерным TLS-отпечатком) с полным набором браузерных заголовков
- **HTTP Engine (curl_cffi)** — опциональная имперсонация браузерного TLS-отпечатка (JA3/JA4/HTTP2) для скачивания и фолбэк-загрузок (см. [HTTP Engine (curl_cffi)](#http-engine-curl_cffi))
- **Авто-эскалация на блокировку** — при HTTP 403/5xx один запрос через curl_cffi (bounded, прозрачен для карантина)

### Система паттернов
- **Встроенные паттерны** — готовые правила для популярных сайтов
- **Custom patterns (JSON)** — собственные правила с `image_transformations`
- **Imagus Sieve** — загрузка правил Imagus; JS-правила конвертируются в Python callables
- **JS Engine (Deno)** — опциональный лёгкий JS-движок: выполняет JS-правила sieve в песочнице (подробнее в разделе [JS Engine](#js-engine-deno))
- **Page only режим** — скачивание только с указанной страницы без обхода сайта

### Очередь задач
- **Мультизадачность** — очередь с паузой/продолжением каждой задачи
- **Page only режим** — чекбокс для скачивания только с текущей страницы
- **Автозапуск** — следующая задача запускается автоматически при завершении текущей
- **Экспорт/Импорт CSV** — выгрузка и загрузка очереди из CSV-файла
- **Очистка истории** — удаление очереди и session-файлов (скачанные файлы сохраняются)

### Загрузка
- **Многопоточность** — настраиваемое число потоков парсера и загрузчика
- **Multi-threaded download** — загрузка одного файла несколькими потоками (с `Accept-Ranges`)
- **Общая HTTP-сессия** — переиспользование TCP/TLS-соединений
- **Контроль скорости** — ограничение пропускной способности (действует на однопоточные загрузки; при «Threads per File > 1» не применяется — `Audit.md`, DL-12)
- **Дедупликация** — пропуск уже загруженных URL
- **Атомарное сохранение** — state.pkl через temp + fsync + rename (защита от аварий)

### Портабельность
- **onedir сборка** — все файлы приложения в одной директории
- **Относительные пути** — ресурсы, настройки, session — всё рядом с exe
- **Скачивание в выбранную папку** — путь запоминается между запусками

### Поддержка форматов
- **Изображения:** JPEG, PNG, WebP, AVIF, BMP, TIFF (GIF/SVG/ICO/CUR по умолчанию выключены, включаются в *Settings → Filters*)
- **Видео:** MP4, WebM, OGG, MOV, MKV, AVI, FLV, M4V
- **Аудио:** MP3, WAV, AAC, FLAC, OPUS
- **Streaming:** M3U8 (HLS), MPD (DASH)
- **API:** JSON-эндпоинты — *(в текущей версии извлечение из JSON сломано: `Audit.md`, CORE-1; чинится однострочной правкой)*

### Браузерное расширение (Chrome/Chromium)

Расширение работает как точка входа для desktop-приложения и как самостоятельный загрузчик.

**Режимы работы:**

| Режим | Кнопка | Что делает |
|-------|--------|------------|
| **Page only** ✓ | Download | Сканирует страницу → список выбранных медиа отправляется в desktop-приложение (задача one-shot) |
| **Page only** ✗ | Parse Page | Отправляет URL страницы в desktop → полный парсинг (crawler, sieve, deep crawl) |
| Save (Chrome) | — | Скачивает выбранные изображения напрямую через Chrome downloads |
| Ctrl+Shift+S | — | Сканирует + скачивает все fullsize через Chrome |
| Ctrl+Shift+D | — | Отправляет URL активной страницы в desktop (глубокий парсинг) |

> Примечание: при отправке one-shot списка из расширения задача добавляется в очередь приложения; автозапуск в текущей версии не срабатывает (Qt-таймер из HTTP-потока — `Audit.md`, GUI-1) — нажмите Start в приложении.

**Возможности расширения:**
- Сканирование DOM: `<img>`, `<video>`, `srcset`, `data-src`, CSS backgrounds, og:image
- Обнаружение fullsize: загрузка linked pages → поиск прямых CDN URL через Imagus sieve `res` regex
- Извлечение cookies и User-Agent из браузера → передача в desktop для обхода блокировок
- Фильтрация по домену и типу (Full size / Thumbnails)
- Загрузка custom sieve rules из JSON файла

**Установка:**
1. `chrome://extensions` → Developer mode
2. Load unpacked → выберите папку `extension/`
3. При первом запуске загружаются 849 Imagus sieve rules
4. Можно обновить через "Load sieve rules..." в popup

### Интерфейс
- **PySide6 GUI** — тёмная тема, лог с фильтрацией по уровням
- **Пауза / Продолжить / Стоп** — полный контроль над процессом
- **Прогресс-бары** — общий прогресс и прогресс текущего файла
- **Вывод лога в файл** — опционально через настройки (Settings → Logging)
- **Защита настроек** — валидация всех полей при загрузке (anti-tamper)

- **Python** 3.8+
- **ОС:** Windows 10/11 — основная и тестируемая платформа. Linux/macOS официально не проверяются; установка строго по `requirements.txt` на них сейчас невозможна (маркер `cchardet` не предоставляет модуль `chardet`, который импортирует парсер — `Audit.md`, PKG-3)

git clone https://github.com/Sucotasch/web-media-parser.git
cd web-media-parser
pip install -r requirements.txt
python main.py

## Использование

1. **Запустите** приложение (`python main.py` или `WebMediaParser.exe`)
2. **Вставьте URL** сайта, с которого нужно собрать медиа
3. **Выберите папку** для сохранения файлов (путь запоминается)
4. **Настройте параметры** через *Settings* (по умолчанию оптимальны)
5. Нажмите **Start**

### Дополнительно
- **☑ Page only** — скачивает только медиа с указанной страницы, не обходит сайт
- **Export CSV** — выгрузка очереди задач в CSV
- **Import CSV** — загрузка задач из CSV (восстанавливает завершённые, скачивает новые)
- **Clear History** — очистка очереди и session-файлов

### Структура загрузки

Файлы раскладываются по домену страницы-источника и до 2 компонент её пути (не по типу медиа):

```
<download_dir>/
└── example_com_20260412_1630/       — папка задачи ({домен}_{время})
    └── cdn.example.com/
        └── gallery/
            └── photo.jpg
```

## JS Engine (Deno)

Парсер может выполнять **JS-правила Imagus sieve** через лёгкий движок Deno вместо устаревшего конвертера JS→Python. Движок **выключен по умолчанию** (`Static`) — включите в *Settings → HTTP → JS Engine → Deno*.

### Что даёт
- **P0** — JS `to`-правила (преобразование thumbnail → fullsize URL)
- **P1** — JS `url`/`res`-правила: загрузка linked-страниц и извлечение fullsize через DOM (happy-dom) и сырой текст страницы (`$._`)
- **P0.5/P1.5** — `this.node`-эмуляция: правила с `this.node.closest/querySelector/src` дают результат там, где раньше молча падали
- **Fullsize-дискавери** — переходы thumbnail→страница-оболочка→полноразмерный оригинал (imx.to и др.)
- **P4 — JS-гейты** — consent/age-кнопки: статический парсер кук из `onclick` (всегда) + клик по кнопке в happy-dom (при `js_engine=deno`); мутированный DOM парсится без повторного fetch

### Безопасность
- Воркеры запускаются **без прав** (`--allow-*` не выдаются), скрипты страницы не выполняются — только правила пользователя против DOM
- Офлайн-кэш npm бандлится в `bin/deno_cache/` — движок работает без интернета

### Ограничения (осознанные)
- Правила, которым нужен **реальный элемент браузера** (`this.node.closest(...)` на сложных галереях), fail-open — серверный движок не может дать hovered-элемент
- **Асинхронные** правила (fetch/XMLHttpRequest, `IMGS_ext_data`) несовместимы с синхронным пайплайном и не выполняются
- **Cloudflare Turnstile/Managed Challenge** движок не обходит (требуют реального браузера); помогают cookies расширения (`extension_cookies`) + прокси
- При любой ошибке движка приложение автоматически откатывается на статический парсинг (fail-open)

## HTTP Engine (curl_cffi)

Обычные Python-HTTP клиенты (`aiohttp`, `requests`) используют OpenSSL-стек, чей TLS-отпечаток (JA3/JA4 — без GREASE-токенов, без HTTP/2, python-User-Agent) легко распознаётся как «не браузер». Продвинутая защита (Cloudflare, Akamai, DataDome) может блокировать **на уровне TLS-рукопожатия**, ещё до проверки заголовков. Движок **`curl_cffi`** линкует патченный libcurl (curl-impersonate), воспроизводящий точный TLS/HTTP2-отпечаток реального браузера.

### Что даёт
- **Имперсонация браузера** при скачивании медиа и фолбэк-загрузке страниц — CDN видят «настоящий Chrome» (профиль `chrome` обновляется автоматически)
- Работает там, где `requests`-фолбэк не помогает: блок происходит на handshake, а не на заголовках
- **Fail-open**: если curl_cffi не установлен или профиль не поддерживается — автоматический откат на `requests` с одним предупреждением в логе

### Как включить
*Settings → HTTP → HTTP Engine → curl_cffi (browser TLS)*. Основной асинхронный путь остаётся `aiohttp`; движок применяется к sync-путям (скачивание, фолбэк, гейтвеи).

### Авто-эскалация на блокировку (Escalate on block)
Отдельно от глобального движка работает **авто-эскалация** (включена по умолчанию): когда запрос явно заблокирован — **HTTP 403** или **5xx после исчерпания ретраев** — приложение делает **ровно один** запрос через curl_cffi (браузерный TLS) прежде чем признать неудачу.

- **Bounded by construction**: одна попытка на URL, никаких циклов — эскалация невидима для карантина. Успех → файл/страница получены (счётчик failures не растёт); провал → возвращается та же ошибка, что и без эскалации (карантин работает как раньше).
- **429 не эскалируется** — rate-limit лечится backoff'ом с `Retry-After`, отпечаток здесь не поможет.
- При глобальном `HTTP Engine = curl_cffi` эскалация автоматически отключена (блок уже случился на curl — дублировать бессмысленно).
- Отключается чекбоксом *Settings → HTTP → Escalate on block*.

### Ограничения (осознанные)
- **Не обходит** Cloudflare Turnstile / Managed Challenge и JS-челленджи (нужен реальный браузер); для них помогают cookies расширения + Deno + прокси
- При включённой имперсонации **кастомный User-Agent игнорируется** — профиль предоставляет согласованный набор заголовков (UA + Sec-CH-UA), и его переопределение нарушило бы отпечаток
- Применимо только к sync-путям; асинхронный fetch страниц остаётся на aiohttp (проверен, быстр)

### Ключевые механизмы

**Приоритизация URL** — многофакторный скоринг:
- Прямые медиа-URL ×25, image-linked ×20
- Совпадение пути с начальной страницей ×3+ за компонент
- Домашние страницы и навигация ×0.005
- Репутация домена (сколько медиа найдено)

**Domain concurrency limit** — макс. 2 одновременных запроса к одному домену (парсинг + скачивание).

**Карантин** — домены с 3+ ошибками временно блокируются. Повторная попытка 1 раз, затем URL отбрасывается. Probation timeout 5 сек.

**Natural completion** — автозавершение при пустых очередях (>5 сек без активности).

**Page limit** — останавливает краул после N **страниц-источников, с которых были загрузки** (не файлов и не всех посещённых страниц).

**Imagus Sieve (сторона приложения)** — правила подключаются автоматически в сборке (файл `Imagus_sieve_*.json` рядом с exe) или вручную: *Settings → HTTP → Imagus Sieve file*. В dev-запуске из репозитория автозагрузки нет — файлы в корне не входят в пути поиска (`Audit.md`, PAT-1); укажите путь вручную или положите файл в `resources/patterns/`.

## Устранение проблем

| Проблема | Решение |
|----------|---------|
| Медиа не обнаруживается | Включите **Process JavaScript**, подключите Imagus Sieve (см. «Ключевые механизмы») |
| Низкая скорость | Увеличьте **Downloader Threads** до 16–32 |
| Сайт блокирует запросы | Настройте **Proxy**, увеличьте **Timeout**, включите **HTTP Engine = curl_cffi** |
| 429 Rate Limit | Приложение автоматически делает backoff с Retry-After |
| Приложение «зависло» | Проверьте лог, используйте **Stop** (немедленная остановка) |
| Дубликаты при Resume | Автоматически фильтруются (проверка downloaded_files) |

## Известные проблемы

Полный список с готовыми фиксами — **[`Audit.md`](Audit.md)** (аудит 2026-08-16, два блока: приложение и расширение). Кратко о самом заметном:

- JSON-эндпоинты не парсятся (CORE-1, критично, фикс — одна строка)
- При ошибке единственной страницы задача может не завершиться сама (CORE-10)
- Автостарт one-shot задач из расширения не срабатывает — нажимайте Start (GUI-1)
- Файлы с `Content-Encoding: gzip` могут ложно отбраковываться по размеру (DL-3)
- Ограничение скорости не действует при «Threads per File > 1» (DL-12)
- Cookies, переданные расширением, уходят всем crawled-хостам, а только исходному домену (DL-7)
